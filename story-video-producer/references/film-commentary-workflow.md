# 影视解说与原片制作流程

用于电影、动画剧集的“旁白＋原片”视频及其局部工作。正文风格交给 `story-video-writer`；这里规定素材怎样支持文案，以及核片结果怎样进入制作。漫画来源另读漫画分支。用户只要求某一阶段时交付该阶段；完整视频任务在已有授权内接着推进。

## 创作默认值与输入

- 默认讲给没看过作品的人听，在约定的作品、季/集或篇章范围内讲清主线；指定安利、片段或剧透范围时按用户要求。不把跨季结局提前用于解释当前人物，也不自行加入 OVA、特别篇或剧场版。
- 默认抖音、横向电影画面、旁白与原对白/表演/现场声音交替。平台、画幅和模式均可覆盖，不设固定时长、原片比例或插入频率。
- 竖屏信息流中的横向播放区域和全屏模式，不等于把播放器黑边、按钮或评论区做进文件。按实际项目检查画幅、字幕和人物可读性，不能保证某个全屏入口出现。
- 复用已有初稿、外部资料、字幕、核片表和工程。来自其他会话的稿件也是待对片的文稿，不因写得流畅就视为事实已确认。
- 先检查 `story-video-writer` 是否可用；同仓库有完整目录时可直接读取其 `SKILL.md` 和引用文件，不把仓库文件存在等同于已安装。都没有时可先整理素材、提出候选和写有依据的草稿，说明缺少约定的写作规则；不自动安装或等待其存在才开始。

## 按材料进入流程

| 已有材料 | 现在可以完成 | 下一阶段需要什么 |
| --- | --- | --- |
| 只有字幕或梗概 | 事件因果、关键疑点、旁白草稿与原片候选意图 | 关键场景的原片或足以核实该问题的材料 |
| 字幕＋可读取的原片 | 核片、旁白与原片共同设计、候选切点验证 | 制作所需素材与用户要求的声音方案 |
| 初稿＋原片 | 检查稿中动作、人物、因果和引用；修改段落及原片安排 | 定稿与实际录音/配音后的时长 |
| 已有剪辑工程或试排 | 找到现有问题，局部回改并复核受影响部分 | 用户要求的导出格式与目标 |

字幕不足时不编造无对白动作。也不要求所有人先生成完整资料包、写公众号文章，或在固定两个应用间往返。信息在哪里可访问，就在那里完成对应工作；只有访问受限或用户选择分工时才交接。

## 1. 字幕与源文件

读取实际文件，区分影片/动画/原著版本。为不同源文件记录稳定的 `source_id`、`source_type`（`film` 或 `animation`）和版本；剧集另记季、集或特别篇标识。电影不必填虚假的集号。多个文件即使都从 00:00 开始，也不能混为同一时间轴。

剧集先沿用用户约定的播放/讲述顺序；存在放送顺序、故事时间顺序、总集篇与正片差异时记清使用哪一种。重复回顾、片头片尾和跨集重播按叙事需要取舍，不能把同一事件算成两次。讲述只覆盖部分集数时，交代必要前情，并保留范围外未揭晓的疑问。

视频在本地可访问时记录时长、帧率、分辨率及所用音轨；大文件可复用已有标识，只有需要跨机器校验时再计算完整哈希。不根据文件名推定技术参数。

解析 ASS/SRT 的时间和内容，保留源位置。对白、旁白、画面文字、字幕组注释和歌词分开；ASS 的 `Dialogue` 行不一定是人物对白，样式也只能辅助分类。Name 为空时不能凭字幕确定说话人；PlayRes 是排版坐标，不等于视频尺寸。两种语言字幕若同源，不当作两个独立权威来源。

对每个使用的源文件，用前、中、后的可辨认位置核对字幕同步；若偏移随时间变化，查清版本、分段或速率问题，不套一个固定偏移到全片或整季。未同步前只标字幕时间，不能标为已验证源视频切点。

## 2. 故事与候选原片一起设计

围绕人物目标、选择和后果梳理因果。补资料先针对具体疑点，区分作品事实、人物陈述、推断与主题解读。字幕注释只能提供检索线索；原著补充和现实理论需明确来源，不能补成当前影视版本实际发生的镜头。混用漫画图格说明改编差异时，标明漫画版本与页格来源，不把它冒充动画缺失的镜头。

调用视频写作 skill，把旁白和原片在同一轮安排：旁白压缩过程和交代必要前情；原片承担关键消息、选择、表演或情绪。入原片前不把它全部讲完，出来后优先讲后果，避免重复复述。

只有字幕时，能决定“这里值得让人物自己说”，尚不能决定表演是否有效、反应镜头长度、声音衔接或最终剪辑点。候选写明目的与待核问题；不为了凑时长而拼接原本没有相互回应的对白。

## 3. 对原片核查

优先检查会改变剧情理解、依赖动作/表演、字幕存在分歧，或准备让原声独立承担叙事的场景。用字幕、粗略场景索引或已有缩略图定位，再对疑点局部加密；不把整部电影逐帧送给模型。

实际提取使用当前可用的媒体工具或 FFmpeg/ffprobe。先确认输入、输出和版本支持，写到独立输出目录，保留源素材。核查结果至少能回到实际源文件与源时间。

- **静帧**可以确认可见人物、物件、字幕牌等；稀疏静帧不能证明整段连续动作、因果或完整表演。
- **连续动作**要查看足够的连续画面或合适工具支持的片段；语气、声源与音乐衔接要实际听取声音或用能支持该判断的证据。提取音频成功、自动转写完成都不等于听过原声。
- **字幕冲突**对照上下文与原声，修正说话人、主客体、否定、条件和时态；某一语言文件也可能有误。
- **片段切点**在上下文成立后验证，保留完整语义、动作和必要反应。字幕显示边界只是定位线索，不直接用作剪辑边界。

没有足够视听能力时，只完成可证实部分，把具体缺口写入交接。不要把猜测升级为已核实，也不要因此放弃已有依据的故事草稿。

## 4. 核片后回改文案

先列对故事有影响的“原说法—片中依据—修正说法”，再按视频写作 skill 修改。原片不支持时，允许删改判断、补因果、调整段落顺序和替换候选，不只是润色句子。

优先保留用户立场与表达习惯，但不为了保持初稿而寻找牵强配图。检查旁白、画面和原声合起来是否让新观众听懂；不要求抽走原声后的旁白还能单独成为一篇完整文章。

改了段落、源片或字幕偏移，就同步更新旁白对应关系、原片表和受影响的时间线。不能继续沿用已经失效的旧切点。

## 5. 轻量记录与跨会话交接

只保留当前任务用到的记录，Markdown 表或已有工程格式均可，不强制建一套 JSON 工程。原始字幕与影片版本、讲述范围/顺序、字幕偏移和必要研究来源记一次即可；不同源文件各自保留标识。

| 片段记录 | 内容 |
| --- | --- |
| 标识与旁白关联 | 稳定片段 ID；对应配音稿段落或原片独占位置 |
| 叙事作用 | 这段让观众知道什么，或为什么需要保留动作/声音 |
| 来源与查找位置 | `source_id`、来源类型、版本；剧集的季/集；字幕候选区间与已验证源视频入出点分别记录 |
| 核查依据 | 实际说话人/动作、关键对白；素材已提取、画面已查看、声音已检查、切点已验证分别如实记录 |
| 编排与待办 | 是否选用、前后衔接、实际时长或估算；缺少什么依据 |

尚未写初稿时，旁白关联可留空。源位置写成“源文件/季集＋源时间”，成片位置属于重排后的时间线，不能互换；跨集重组仍要保留每段真实来源。源片同时铺在旁白下方时不额外增加时长。

交给另一会话/本地 Codex 时，提供当前稿件、片段记录、必要素材或可访问路径、关键事实修正和本次目标。写清楚当前能访问什么，不把一台机器上的绝对路径假设为另一台也可访问。足够核查的片段可以优先于整部影片传输。

## 6. 配音、试排与制作

只要求稿件时到此交付：干净的配音正文与原片安排；时间码、段落关联和制作指令不进入配音正文。未核实项目保留候选状态。

用户要求完整成片时，在已授权范围内继续：完成实际配音/录音后，用原声片段一起试排，再修正语速、旁白长度、片段切点和停顿。粗估旁白可暂用每分钟 220—280 个中文字，实际声音取代估算。独占原片和未覆盖停顿另计，重叠只计一次。

- 原片对白承担内容时，旁白通常退出；保留必要环境声和反应。避免两套完整讲话抢同一时刻，也避免前后旁白重复解释。
- 配音字幕对应实际旁白，原片字幕对应实际对白。发现字幕组注释/硬字幕干扰画面时据素材选择处理方式，不假定能无损去除，也不能误删叙事信息。
- 配乐和响度根据实际听感与用途调整，不把固定音量数字当成混音完成的证明。
- 原片剪辑复用现有编辑方式；需要动画字幕、标题或图形说明时可接 HyperFrames。不要为了路由而重建已有工程。
- 超时先删重复、调整事件详略与原片边界。不用持续加速、截断对白、删除关键因果或未经同意拆系列来硬凑。

没有原片或关键事实仍未解决时，可以交草稿/试排，但不能称为可发布终稿。已明确授权完整制作时，不在每一步重复询问；只在缺失输入、必要选择或未覆盖的外部操作处说明具体原因。

## 7. 成片检查

检查实际导出的画面与声音：新观众能否认人并跟上因果，原片与旁白是否重复或断裂，字幕是否同步和可读，是否有黑帧、冻结、明显音量突变或被截断的话语。重点检查修改处、转场和开头结尾；涉及全片一致性的问题用适合的工具检查，不能只看封面就宣布通过。

将发现的问题回写到稿件、片段表或工程，再复核受影响的部分。交付时说明检查覆盖与未解决事项，完成渲染不等于完成视听检查。上传、发布及新付费服务按具体授权执行，不从“做视频”推定这些操作均已授权。
