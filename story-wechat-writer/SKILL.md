# 公众号故事解说写作

像给朋友分享一个值得讲的故事，让没看过作品的人也能听懂、进入情境，并想知道接下来发生什么。默认优先把故事讲清楚，再照顾讲述节奏，在关键处加入有场景支撑的个人理解。

默认读者没有看过作品，默认剧情解说以本次约定范围内的完整主线为目标；这不意味着逐镜头复述，也不意味着必须隐藏结局。用户要求安利、限制剧透、只讲片段或进行角色解析时，按本次任务调整。

使用自然、有个人判断的中文。作品本身的气质、用户观点和参考稿优先于这里的风格倾向。用户只要求润色时，保留原稿的立场、剧情范围和完成度，不擅自扩成整部作品的解说。

## 动笔前的取舍

根据现有信息确定作品版本、剧情范围和详略。没有明确要求时，面向初次接触作品的人组织材料。只在缺失信息会实质改变稿件且无法合理判断时询问，不先交付策划表或一串问题。

| 本次任务 | 内容重心 |
| --- | --- |
| 故事分享与完整剧情解说（默认） | 以事件因果推进，交代必要背景、人物关系与转折，让人理解事情如何发展到结局 |
| 重点梗概或安利 | 压缩支线，保留作品吸引力与必要情境，按要求控制结局和谜底 |
| 角色解析 | 围绕欲望、处境、选择和变化组织材料，补足理解这些场景所需的背景 |
| 单场景解读 | 细看动作、对白、镜头或漫画分格，区分观察与解释 |
| 作品评论 | 围绕有材料支撑的判断展开，兼顾能挑战该判断的情节 |

用户的观点可以作为起点。素材不支持时，指出具体矛盾并建议更贴切的表达，不为顺从立场扭曲剧情。

## 六个核心写作原则

### 1. 从具体情境里生出好奇

从一个处境、动作、关系变化或异常事件切入，让读者想知道接下来发生什么。开头可以提出问题，也可以直接把故事讲起来，不规定必须反问或先抛高潮。

不要先铺作品地位、评分与获奖履历，除非它们直接关系到本次讲述。悬念来自作品里真实存在的矛盾，不靠夸大评价、伪造伏笔或隐瞒必要信息制造。

### 2. 让第一次接触故事的人跟得上

在需要时自然交代人物是谁、身在何处、想做什么，以及什么阻碍了他。多人对话或场景切换时，宁可重复名字，也别让代词造成混淆。

影响当前事件的世界观规则先讲清，其余设定随故事补充。陌生术语先用通俗说法解释，再决定是否需要保留名称。一句话不要塞进多个新名字、设定和判断。

保留推动剧情、交代关系与空间、支撑判断或形成情绪的动作细节。删去不增加理解的画面复述；不能因为画面已经展示，就省略只读文章的人仍然需要的信息。

### 3. 让故事沿着因果向前走

默认围绕“发生了什么—人物如何应对—引出了什么后果”组织。重点让人理解上一件事为什么引出下一件事，不机械罗列全部事件。

可以从高张力场景切入再回溯，也可以按时间、地点或视角转换推进。回溯与切换要有清晰落点，不让读者额外猜测先后关系。

保留理解后续情节所需的铺垫，不因追求快节奏一律压缩背景或支线。战斗不只列招式，还要说明双方争取什么、局势如何改变。平静的一幕或没有说出口的话也可以推进故事。

悬疑作品按讲述需要控制信息揭示，避免过早交代角色真面目与最终答案。详细解说可以讲到结局，悬念依靠过程中的信息顺序维持。

### 4. 在值得停一下的地方加入判断

让读者先看到行为和结果，再在重要抉择、关系变化或后果出现时说出理解。允许连续讲完一段情节，不要求剧情和评论按固定间隔轮换。

可以喜欢、质疑或吐槽一个角色。判断要落在他知道什么、想保住什么、有什么选择以及付出什么代价上。理解处境不自动等于赞同行为。

不要人物刚登场就替读者下完结论，也不要每个动作后面都补一句心理分析。删去评价后，场景已经足以表达的意思，可以留给读者自己感受。

文本未明确的动机，用“我更倾向于理解为”“这里也可能是”等自然表达标示解读，不把讲述者的推测写成作品确认的事实。

### 5. 像朋友聊天，让情绪有自己的节奏

用自然转场连接情节，长短句交替。重要节点允许停顿和留白，不强求每段反转、每段升华或每段笑点。

“我觉得”用来承担判断，“你”用来邀请观察，不必反复出现。不强塞口头禅、粗口、网络梗或连续反问。轻松处允许玩笑，失去、告别和重大抉择处给情绪留空间。

复杂背景先用具体处境讲明白，避免连着堆概念、分类和抽象结论。外部知识只解释眼前的疑问，解释完就回到故事。

### 6. 让结尾回应这一路的经历

交代本稿范围内的结果，让读者知道人物和局势发生了什么变化。开放结局区分已经发生的事、镜头暗示和讲述者的理解，不替作品补出后续。

选一个与主线有关的动作、物件或问题，在剧情提供对应时自然呼应。没有合适对应，就落在故事的结果或人物的一次选择上，不硬凑回环。

只有剧情足以支撑时才延伸到现实经验或更大的主题。不用重复总结整篇观点，也不自动加关注口号。

## 按公众号组织文字

让文章脱离配图也能读懂。保留必要的场景细节、关系铺垫与个人观察，段落适合手机阅读。默认用叙事转场连接全文；作品跨度大且有助辨认行程时，可以用地点或阶段作简短分隔。用户要求论点式评论或明确要求小标题时再相应调整。

把“你看这里”落成具体场景描述。可以重组材料，但要保持因果和时间关系清楚，不机械扩写口播，也不把文章写成概念讲义、研究报告或逐项分析清单。配图能强化情境，主线的关键信息仍应进入正文。

同一素材需要视频版时，将已整理的事实与来源交给 `story-video-writer` 独立组织旁白和视觉段落。公众号稿不沿用口播的留人句、原片插入指令与互动尾巴。

## 按原作类型取材

| 原作材料 | 写作时需要辨明的内容 |
| --- | --- |
| 电影、动画电影 | 指定剪辑/发行版本；字幕可定位对白，静帧不能独自证明连续动作或声音 |
| 动画剧集 | 季、集、篇章和本稿截止处；特别篇、总集篇与正片分开，跨集闪回或重播不写成新发生的事件 |
| 漫画、条漫 | 版本、卷/话/章、页与格、阅读顺序；先认清谁在说话，区分气泡、内心独白、旁白框和拟声词 |

“完整”以已确定的范围为准：只讲第一季就收在第一季，只讲某章就交代这一章的结果。持续连载或开放结局不补出尚未给出的后续。未知集数、页码或阅读方向不要猜。

漫画文字转录或 OCR 可以帮助找情节，但说话人、表情、动作先后和跨格关系需要查看原页。排版、留白和翻页可以影响阅读感受；将两格间未画出的过程描述为推断，不把静态漫画写成已经出现的镜头运动或配乐。条漫没有固定页码时，用图文件和纵向区域定位，不制造书籍页码。

写影视改编时，漫画原著的情节只能作为标明来源的补充；写漫画时，也不能把动画原创情节、声优语气或配乐当成漫画已有表达。比较改编时可以并列讨论，始终说清各自出自哪个版本。

## 素材、查证与外部补充

遵守用户指定的作品版本、篇章和剧透范围。动画、漫画、小说、真人改编，以及电影的不同剪辑版本不混作同一事实来源。片名或版本存在会影响内容的歧义时先确认对象。

优先使用用户提供的原片、字幕、原稿与素材。需要外部补充，或对影响主线的情节、台词、设定拿不准时，使用可用检索工具核实；优先作品本身、官方资料、创作者正式访谈，再用可靠评论交叉检查。搜索摘要与其他人的解说稿不能单独支撑存疑的关键情节。

精确台词、访谈与制作背景需要可靠依据。无法确认时用明确意译、删除非必要细节，或向用户指出仍缺少的关键材料。没有真实集数与时间码就不添加，不把镜头解读说成导演确认的意图。

补充其他版本或原著时用“漫画原著里……”等简短提示标明来源，只在有助理解本稿对象时使用，不把被删改的情节塞回当前版本。作品事实、其他版本和讲述者解读的边界要让读者读得出来。

现实理论与历史资料用于帮助理解作品的设想，不能把虚构机制写成已经成立的科学结论。背景补充控制在能接住当前疑问的篇幅，随后回到人物和事件；引用按交付环境要求提供可追溯来源，避免整篇被资料说明打断。

关键剧情材料仍不足时，先完成有支撑的部分，再询问必要信息；不编造细节补齐一篇看似完整的稿子，也不把未核实草稿当作可发布定稿。

素材不足时，先交有依据的局部草稿或带归属的片段介绍，在正文外说明尚未完成的范围与影响续写的缺口；未知说话人不能为求顺口补成具体角色。OCR、文件页和待核状态留在正文外；不要把核查过程讲成故事，也不要把尚未核实的信息包装成作品有意留下的悬念。

可以表达对材料的判断，不虚构用户的观影经历、童年记忆或亲身遭遇。需要私人经历时使用用户真实提供的细节。

## 风格示例

以下为虚构练习，不对应任何现有作品：少年平时总催队友快走。这次队友受伤，他停下脚步，嘴上仍说“不想等你”。

平铺写法：队友受伤了，少年停下来等他。这说明少年虽然嘴硬，但还是关心队友的。

故事分享写法：这一路，少年一直嫌队友走得慢。可等两个人准备离开，队友却没跟上来。他回过头，才发现对方已经扶着墙，伤腿再也使不上力。那句“不想等你”还是说出了口，人却留在了原地。

需要加入判断时可以接：平时总催别人快走的人，这一次自己停了下来。把前后放在一起，他们之间的变化就清楚了。

示例展示如何由情境进入事件、再酌情加入理解，不作为固定句式，不挪作真实作品的剧情。

## 交付前检查

从第一次接触作品的读者角度通读：人物、地点与先后关系是否清楚；关键转折是否有铺垫；有没有突然出现的设定；必要的情节是否因评论而被挤掉。

确认事实、版本、外部补充和个人解读的边界，删去无依据细节与多余的评价。检查故事是否完成本稿承诺的范围，开头的问题是否得到回应，载体、长度与剧透要求是否符合用户意图。

默认交付正文，必要的资料出处和待核问题放在正文外，不附策划表、评分表或固定关注口号。用户只要求润色时只改相应内容；需要提取截图/漫画图格、图文排版或 DOCX 时由 `story-wechat-producer` 接续，不把写稿说成已完成配图制作。
